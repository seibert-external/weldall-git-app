# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- The service, its configuration, API and image are described in `README.md`; scripts in `package.json`. Gates: `pnpm typecheck`, `pnpm test`, `pnpm format:check`, `pnpm image:test`. Both test commands need Docker: `test/setup/database.ts` (vitest `globalSetup`) starts a throwaway PostgreSQL unless `GIT_APP_TEST_DATABASE_URL` is set, and `scripts/test-image.sh` starts one on a private network.
- The app registry (INV-183) lives here, not in Weldall: `src/registry/` (postgres.js, plain SQL). Migrations in `src/registry/migrations.ts` are append-only and run at every start; never edit a shipped one. Every query is unqualified so the tests can give each instance its own schema (`test/fixtures/database.ts`). Registry and audit changes that must count together (confirmation, registering an existing repository) run the audit report inside the registry transaction; keep that order.
- The Git app serves exactly one Git host per instance (drivers in `src/hosts/`, git proxy in `src/git/`, streamed, limits in `src/git/limits.ts`). Weldall never talks to a Git host, and no host token leaves this service.
- Every GitHub token is restricted to one repository and operation, except repository creation, which deliberately uses the unrestricted installation token because GitHub refused every narrower one in live tests (`mintRepositoryCreationToken` in `src/hosts/github/tokens.ts`). Do not widen any other token.
- `src/app-host.ts` is a copy of Weldall's app host contract (`apps/weldall/src/server/app-host/contract.ts` in seibert-external/weldall, not part of `@weldall/sdk`; scope `weldall:app-host`, the machine client must be allowed for this resource): only audit events and the subject scope check. Weldall is the authority. `test/fixtures/app-host/audit-event-request.json` must stay identical to Weldall's copy (`apps/weldall/test/fixtures/app-host/`); `test/app-host.test.ts` asserts the client sends exactly it. Change both repositories together.
- `src/redaction.ts` must stay identical in its rule list to Weldall's `apps/weldall/src/server/observability/redaction.ts`. No cross-repository test exists; compare by hand whenever either changes.
- The Docker image (`Dockerfile`, `scripts/build-image.mjs`, `scripts/test-image.sh`) builds from this repository's root and bundles `@weldall/sdk`, so an SDK bump needs a new image. The bundle script fails when a bundled package has no license file; keep that. Its only exception, `DECLARED_LICENSES`, holds `postgres` (Unlicense, declared in package.json only); do not add packages to it without checking their license.
- CI is `.github/workflows/ci.yml` (it sets `GIT_APP_TEST_DATABASE_URL` to a service container and raises its `max_connections`, as the local test container does). Images are published only by `.github/workflows/release-image.yml` from a GitHub release tagged `v<package.json version>` on `main`; helpers and their tests in `scripts/image-release.mjs` and `test/image-release.test.ts`. The Docker Hub secrets live only in the `release` environment, which must keep required reviewers. Actions are pinned by commit SHA, checkouts use `persist-credentials: false`, and workflow permissions stay `contents: read`; keep that. Never run the release workflow from an agent session.
- This repository is public. Never commit credentials, internal hostnames, real GitHub App or installation IDs, or names of real organisations, repositories or people; tests and docs use `example.com`, `example-apps`/`acme-apps` and generated keys. Fake credentials in tests are assembled at run time so no file holds a string that looks like a real one.

Keep this file for knowledge useful to almost every future agent session in this project.

Prefer rewriting or pruning existing entries over appending new ones.
When updating this file, preserve this bar for all agents and keep entries concise.
